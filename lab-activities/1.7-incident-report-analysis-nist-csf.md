# 1.7 Incident Report Analysis: Denial of Service (DoS) Security Incident

## Summary
A multimedia organization experienced a Denial of Service (DoS) security incident that disrupted internal network availability for two hours. A flood of incoming ICMP packets overwhelmed network resources due to an unconfigured firewall. The incident response team contained the incident by blocking incoming ICMP packets, taking non-critical network services offline, and restoring critical operations. To prevent recurrence, security measures were implemented, including firewall rate-limiting rules, source IP address verification, network monitoring tools, and an IDS/IPS system to filter suspicious ICMP traffic.

---

## Incident Analysis (NIST Cybersecurity Framework)

| NIST CSF Function | Incident Response & Mitigation Details |
| :--- | :--- |
| **Identify** | An ICMP flood Denial of Service (DoS) attack compromised the internal network for two hours, preventing normal internal network traffic from accessing resources. This disrupted critical business operations, including web design, graphic design rendering, and social media marketing services. The attack exploited a vulnerability in an unconfigured firewall, which allowed a continuous flood of incoming ICMP packets to overwhelm network resources. |
| **Protect** | To prevent similar attacks, the cybersecurity team hardened network perimeter defenses by implementing new firewall configurations:<br>• **Rate Limiting:** Configured new firewall rules to limit the rate of incoming ICMP packets, preventing potential floods from overwhelming network bandwidth and resources.<br>• **Source IP Verification:** Enabled source IP address verification on the firewall to inspect incoming ICMP packets and filter out spoofed IP addresses. |
| **Detect** | To improve visibility and rapidly identify future incidents, the security team implemented continuous network detection tools:<br>• **Network Monitoring Software:** Deployed to track network traffic baselines and detect abnormal traffic patterns or unexpected spikes.<br>• **IDS/IPS System:** Configured to inspect incoming ICMP traffic, filter packets based on suspicious characteristics, and alert analysts to potential attacks. |
| **Respond** | In response to an active Denial of Service attack, the incident response team executes the following procedures:<br>• **Traffic Blocking & Containment:** Immediately configure the firewall to block incoming ICMP echo requests and drop packets originating from unverified or spoofed source IP addresses.<br>• **Service Isolation:** Temporarily take non-critical network services offline to preserve bandwidth, conserve system resources, and reduce server load.<br>• **Operational Continuity:** Prioritize and maintain essential internal network services to ensure critical business operations continue during mitigation. |
| **Recover** | To restore normal operations and confirm the environment is secure, the team will complete the following checklist:<br>• **Service Restoration:** Progressively bring all internal services back online, ensuring web design, graphic design, and social media services are fully functional.<br>• **Traffic Verification:** Validate that internal network traffic flows normally and baseline bandwidth is restored.<br>• **Control Validation:** Verify that newly implemented firewall rules (rate limiting and IP verification) and continuous monitoring mechanisms (IDS/IPS and network monitoring) are active and functioning correctly.<br>• **Documentation:** Complete an incident post-mortem report to record root cause analysis and future prevention measures. |

---

## Reflections / Notes
* **Root Cause Analysis:** The incident succeeded because an unconfigured firewall allowed an overwhelming incoming flood of ICMP packets to saturate network bandwidth, creating a single point of failure that took two hours to identify and resolve.
* **Key Takeaways:** Implementing defense-in-depth through proactive firewall filtering, automated IDS/IPS packet inspection, and continuous traffic monitoring ensures rapid automated detection and containment, significantly reducing future response and recovery times.
